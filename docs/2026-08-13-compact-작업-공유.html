BranchPort compact 작업 공유

프롬프트 재설계 · 평가 지표 구축 · 용어 부록 — 2026-08-13 작성, 팀 공유용

BranchPort의 compact는 Claude Code 세션 로그(~/.claude/projects/**/*.jsonl)를 다른 세션으로 이어갈 수 있는 이관 패키지로 압축하는 기능입니다. 핵심 설계는 "LLM 요약에만 맡기지 않는다"입니다 — 파이프라인은 3단계로 나뉘고, 사실은 기계가, 서사는 LLM이 맡습니다.

① 구조 접기레코드 수백~수천 개 → 턴 단위무손실 · 펼치면 100% 복원
→
② 사실층수정 파일 · 명령 · 에러를 기계 추출결정론 · 수정 파일 recall 100%
→
③ LLM 요약층목표 · 결정 · 상태 · 남은 일프롬프트 v3.8.1
→
full md 패키지②+③ 합본평가 대상

1요약 프롬프트 재설계 — v3.5 → v3.8.1

각 버전은 실측에서 발견된 구체적 실패를 고치고, 같은 지표로 회귀 확인 후 채택했습니다.

버전무엇을 고쳤나실측 효과
v3.5수치 보존 규칙 — 개수·버전·측정값을 원문 그대로 유지QA 보존율 86% → 92%
v3.6언어 보존 — 영어 세션에 한글 요약이 섞이는 비결정 누출 발견(운영자 언어 설정, 모델 무관). 서버 쪽 결정론 판정 + 명시 지시 + 위반 시 재시도위반 3건 → 0건
명령 캡 60사실층 명령 목록 20개 캡을 60으로 상향명령 recall 65~81% → 97%
v3.7→v3.8목적 프로파일(continue / bugfix / handoff) — 일반론 지침을 실측 기반으로 재작성4세션×4조건×10문항 A/B
v3.8.1handoff에서 열거·에러 식별자가 서사에 밀려 탈락 → "Narrative never eats facts" 가드 추가handoff 75% → 80%

목적 프로파일별 QA 보존율(동일 질문지): 목적 없음 80% · continue 85% · bugfix 83% · handoff 80%. key-fact(수정 파일) recall은 목적과 무관하게 100% — 사실층이 기계 병합이기 때문입니다.

2평가 지표 구축 — "압축이 잘 됐다"를 수치로

압축 성능의 단일 표준 지표는 없습니다(조사 결론). 학계 관행대로 절약율 + 보존율 2축 동시 보고를 원칙으로 지표를 직접 만들었습니다.

지표 체계

  • QA 보존율 — 트랜스크립트에서 질문 생성 → 패키지만 보고 답변 → 이진 채점. 방어 장치: 무맥락 대조(패키지 없이 답하면 0% — 질문이 새지 않음), "모름"=오답 결정론 가드, 저장 판정 2,378건 감사 위반 0
  • key-fact recall — 수정 파일·실행 명령을 결정론 스크립트로 채점 (LLM 채점 아님)
  • 사람 검수 — 블라인드 41건, LLM 채점과 일치 90% · κ=0.61, 불일치는 2:2 대칭(한쪽으로 부풀리지 않음)
  • 컷 곡선 — 압축 구간 크기별 트레이드오프 16점 실측

하이라이트 — Claude Code 내장 /compact와 맞대결 (61세션)

내장 요약을 재현하지 않고, 실제 프로덕션 auto-compact가 세션에 남긴 진짜 산출물과 같은 구간·같은 질문지·같은 정답지로 비교했습니다. 11세션에서 시작해 SWE-chat 공개 데이터셋에서 경계 보유 세션을 두 차례(+30, +20) 추가해 61세션·610문항으로 확장했고, 초기 11세션도 같은 질문지로 v3.8.1 재측정해 61세션 전부 동일 프롬프트 기준입니다.

정직하게 — 절약율은 내장이 더 높다

같은 구간을 내장은 78.0%, 우리는 68.5% 줄입니다(우리 패키지가 사실층·diff 앵커를 담아 평균 1.6배 큼). 그래서 절약율 단독 보고는 하지 않고 항상 보존율과 함께 봅니다 — 10%p 더 줄이는 대가로 내장은 질문 3개 중 1개를 못 맞히게 됩니다. 손실 모드도 다릅니다:

  • 내장 오답엔 완료↔미완료를 뒤집은 상태 왜곡 2건 존재. 우리 오답은 "모름"과 경미한 부정확뿐, 왜곡 0건
  • 내장이 729자짜리 요약으로 붕괴한 세션 발견(en-09c156ba): QA 0/10 · 파일 recall 0/14
  • 내장의 최약점은 명령(18%) — "무슨 명령을 실행했었나"를 거의 남기지 않음
  • 절약의 반대편 비용도 실측 — 내장이 소실한 파일을 재개 후 다시 읽는 재탐색 비용(하한)은 61세션 합으로 내장이 아낀 컨텍스트의 36%. 소실이 실제 발생한 12세션만 보면 재탐색(13.6만자)이 절약(14.1만자)과 맞먹음(0.97×, 하한인데도) — 더 줄인 만큼 나중에 도로 낸다

3용어 부록 — 압축 구간 밖에서 정의된 용어 지키기

압축 구간 앞쪽에서 정의된 용어·개념은 구간 요약만으로는 살아남지 못합니다. 이 사각지대를 실측하고 부록으로 메웠습니다.

23% — 부록 없음 (문제 크기 베이스라인)
33% — 부록 v1 (용어 자동 판별 + 첨부)
40% — 부록 v3 (개선 반복, 회귀 0)
범위 밖 정의 QA 보존율 · 잔여 60%는 값·사건형 질문 = 부록이 아니라 /expand(원문 펼치기)의 영역
  • 비용: $0.152/세션 (compact 1회와 맞먹음). 판별 모델을 haiku로 내리면 비용 −58%지만 보존율 −9%p → 기본 sonnet 유지
  • 발단이었던 SKILL.md 방식은 검증 결과 부적합 — 조사 문서 §2에 사유 기록
