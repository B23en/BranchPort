# 시중 기술 비교 검수 — 리트리버·시각화·스킬 (2026-08-13, 화수)

세 영역을 각각 전담 조사(웹 검색 + 코드 대조)로 검수한 결과의 통합본입니다.
원칙: **과장 금지.** 앞선다는 주장은 구조적 근거가 있는 것만, 뒤처지는 것은 뒤처진다고 씁니다.
제출물·발표 문구 작성 시 이 문서의 표현 수위를 상한으로 삼아 주세요.

## 1. 한 줄 결론

| 영역 | 판정 |
|---|---|
| 리트리버/장기기억 | 방향(BM25-라이트+그래프+원문 보존+인프라 0)은 2026 업계 흐름과 일치. **임베딩 부재는 진짜 격차**이나, "A/B 실측 → 회의 결정" 순서가 옳음이 재확인됨 |

## 2. 비교 대상 (조사 범위)

- **장기기억**: mem0, Letta(MemGPT), Zep(Graphiti), LangMem, Claude Code 네이티브(CLAUDE.md), Cursor Memories(2026 초 철회됨), ChatGPT memory, claude-mem, memsearch(Zilliz)
- **시각화**: LangSmith·Langfuse·Braintrust·W&B Weave(옵저버빌리티 SaaS), Claude Code `--resume`, **동일 데이터 소스 직접 경쟁 3종**(claude-code-history-viewer, claude-session-visualizer, claude-code-canvas), 대화 분기 캔버스류(Nodea, tldraw branching 등)
- **스킬**: Anthropic Agent Skills 공식 스펙·skill-creator, Voyager, AutoGen Teachability, Agent Workflow Memory(ICML 2025), OpenAI Dreaming V3, Reflexion, AEVS류 grounding 연구(2026)

상세 비교표는 각 조사 원문 참조(팀 공유 시 요청).

## 3. 우리가 실제로 앞서는 점 (근거 있는 것만)

1. **소급 커버리지** — mem0·Letta·Zep·claude-mem 전부 설치 시점부터 캡처. 우리는 디스크의 기존 JSONL 전체를 채굴하므로 설치 이전 과거까지 즉시 검색.
2. **원문(verbatim) 보존** — 경쟁 시스템은 LLM 추출·요약본만 저장(원문 소실). 우리는 `/api/expand`로 항상 원문 인출. 2026 논문(arXiv:2601.00821 "Verbatim Chunks Beat Extracted Artifacts")이 같은 방향을 지지.
3. **인프라 0** — 벡터DB(mem0)·Postgres+pgvector(Letta)·그래프DB(Zep) 없이 순수 JS 인덱스 파일. "완전 로컬"을 실제로 지키는 드문 사례.
4. **조합적 차별점(시각화)** — 트리+포크 포탈+캡슐 접기+압축 핸드오프 문서 생성+갈래 대화를 한 정적 페이지에 묶은 조합은 조사 범위에서 유일. 주제 렌즈(LLM 분할→행 배치)와 압축 패키지는 유사 사례 자체가 없었음.
5. **결정론적 원문 대조 검증(스킬)** — Voyager·AutoGen·AWM·Reflexion 모두 증류물과 원본의 기계적 대조가 없음. 우리 groundingCheck는 LLM-judge가 아닌 순수 함수라 검증 자체가 환각할 여지가 없고 단위 테스트 가능. 증류 후보 감지는 추가 LLM 호출 0회.

## 4. 뒤처지는 점과 흡수 우선순위

### 지금 반영 (의존성 0 유지, 저비용)
- ✅ **(반영됨)** SKILL.md의 비표준 `when_to_use` 필드 제거 — 공식 스펙 외 필드는 엄격 검증 경로에서 하드 에러 가능. 트리거는 description에 이미 흡수돼 있었음.
- **토큰·비용 통계** — 경쟁 도구(LangSmith·Weave·CCHV·session-visualizer) 전부 갖춘 기본기인데 우리만 없음. jsonl usage 필드가 이미 있어 파서 확장만으로 가능. **흡수 항목 중 ROI 최대.**
- **검색 히트를 챕터 바에 점으로 표시** — 세션 리플레이 업계(Datadog·Kibana) 표준 문법. 기존 챕터 바 재사용이라 저비용.

### 설계 선결 후 도입 (공식 A/B와 연동)
- **시간·세션 근접성 가중** — mem0도 제공하는 표준 기법(recency boost)이고 우리 실측의 실패 패턴과 정확히 일치. 단 현 `/api/search`에는 "무엇에 가까운가"의 앵커 파라미터가 없어 설계가 선결. 과튜닝 방지 위해 공식 A/B 후 상수 확정.
- **AND 부스트 커버리지 비례화** — 실측에서 방향 확인됨(홀드아웃 100%). 지수는 A/B에서 확정.

### 팀 회의 안건
- **임베딩(Ollama 선택층)** — 업계 기본값(BM25+임베딩+RRF)과의 격차는 사실. Ollama형은 npm 의존성 0 실현성 검증 완료.
  **8/14 헤드룸 실측 추가**: 실코퍼스(708턴)에 패러프레이즈 질의 9개(식별자 없이 동의어로)를 날린 결과 top3 성공 3 · 경계 2 · **실패 4** — 실패 전부 동의어 갭(알약↔캡슐, 색약↔색각, "첫 등장 위치"↔earliest). 같은 코퍼스에서 식별자형 질의는 r@3 98.3%. 즉 **임베딩이 필요한 실패 클래스가 실재함이 확인됨** — 식별자형엔 이득 0이므로 대체가 아닌 RRF 융합이어야 함. (n=9·자작 질의라 방향성 근거 — 실사용 질의 중 이 유형의 비중은 팀 질문지 A/B의 몫.) 이 실측으로 회의 안건의 성격이 "필요한가?"에서 "실사용 비중이 얼마나 되나?"로 좁혀짐.
- **신규 대안: 로컬 크로스인코더 리랭커**(BGE-reranker-v2-m3, 278M) — 모델 파일 1개, 서버·DB 불필요. 임베딩 파이프라인보다 가벼운 의존성으로 상위권 정밀도를 올리는 2단계 표준 기법. "의존성 0"을 조금 완화한다면 임베딩보다 리스크가 작은 후보.
- 대회 이후 과제: 스킬 통합/중복제거, 사용 후 피드백 루프, 의미 대조 레이어.

## 5. 하지 말 것

1. **"세계 최초/유일" 문구 금지** — 동일 데이터 소스 로컬 도구 3종 실재, 원문 대조 검증도 AEVS(2026)류 선행 연구 존재. "조합적 차별점"으로만 표현.
2. **"할루시네이션 완전 차단" 주장 금지** — groundingCheck는 토큰 존재 검증이지 명제 참 검증이 아님.
3. **"완전 자동 스킬 증류"·"검수 후 배포 강제" 주장 금지** — 후보 제안까지만 자동이고, 배포를 막는 기술적 게이트는 없음(권장 워크플로).
4. **GraphRAG·시간지식그래프·MemGPT 페이징 모방 금지** — 우리 문제(고정 로그 코퍼스 검색)와 다른 문제의 해법. LazyGraphRAG류 "인덱싱에서 LLM 배제" 흐름도 우리 판단과 같은 방향.
5. **ChatGPT식 요약 사전주입 모방 금지** — 검색이 아니며, 원문 정밀 인출이라는 우리 가치제안과 정반대.
6. **자유 캔버스 전환·멀티 프로바이더 확장·SaaS급 비용 대시보드 금지(마감 전)** — 검증된 노선도 기하를 버리는 일이거나 스코프 리스크.
7. **반면교사: Cursor Memories** — 2025 출시 → 2026 초 철회(예측 불가능한 자동 주입에 대한 업계의 반성). 우리 "능동 호출(스킬)+앵커+옵트인 확장" 원칙을 흔들지 말 것.

## 6. 수치 인용 기준 (제출물용)

- 홀드아웃 60질의: **r@3 96.7%** (검토 하네스, 686턴) / **r@3 98.3%·r@8 100%** (실배포 dist 재측정, 708턴). 인용 시 측정 시점·코퍼스 크기 병기.

- 미니 A/B(패키지 손실 복구): A 8/10 vs B 10/10 — n=10·자작 문항이므로 "방향성 근거"로만 인용, 공식 숫자는 팀 질문지 A/B의 몫.
