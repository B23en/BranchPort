# 압축 손실 보완 리트리버 — 무엇을 어디에 어떻게, 그리고 실측 (2026-08-18, 화수)

회의 설명용 정리입니다. 수치는 전부 실측이며, 측정 방법과 한계를 함께 적었습니다.
관련 PR: #21(하이브리드화·앵커 승계), #22(아키텍처 검토 반영).

---

## 1. 한 줄 요약

> **압축이 버린 맥락을, LLM을 한 번도 더 부르지 않고 되찾아 패키지에 붙인다.**

---

## 2. 왜 필요한가 — 손실은 크고, 무작위가 아니다

- **크기**: 실측 압축 1건에서 원문 20,753자 → 패키지 12,156자. **원문의 41%가 사라진다**(1.7배 압축). 긴 구간일수록 커진다.
- **성격**: 손실은 무작위가 아니다. feat/compact QA 실측에서 오답 18건이 **전원 "정보 탈락"**이었고 환각은 0이었다. 요약이 틀린 말을 하는 게 아니라 **결정은 남고 근거가 끊기는** 방식으로 잃는다.
- **기회**: 요약 LLM이 `open_threads`(결론 안 난 질문·검증 안 된 가설·미구현을 덮은 워크어라운드)를 **스스로 선언**한다. 이 선언이 곧 "손실 지점 지도"이고, 공짜로 나온다.

→ 그래서 **새로 물어볼 필요 없이**, 그 선언을 질의로 재사용해 잃은 것을 정확히 겨냥할 수 있다.

## 3. 어디에 적용되는가

| 경로 | 무엇이 붙나 | 추가 LLM |
|---|---|---|
| **범위 압축** (shift+클릭) | 구조 연결 4건(+원문 발췌 1,400자) · 열린 스레드 4건 | **0회** |
| **노드 갈래 워프** | 질문마다 조상 한정 발췌 상위 3건(4,000자) | **0회** |
| **압축 갈래** | 압축 때 동봉된 것을 md로 승계(20,000자, 앵커 우선 보존) | **0회** |
| **검색창** | 하이브리드 검색(확신 게이트) | **0회** |

## 4. 어떻게 작동하는가 (범위 압축 기준)

```
[1] 압축 LLM 호출 전 ── 구조 연결                        (LLM 0, 임베딩 0)
    범위가 만진 파일·식별자·인접 턴으로 범위 밖 4건 회수
    가중치 1/√(공유 턴 수) · 허브 가드(전체 30% 초과 파일은 신호 제외)
    상위 2건은 원문 발췌 — 발췌 위치는 "가장 희귀한 공유 식별자 등장 지점"

[2] 압축 LLM 호출                                        (LLM 1회)
    프롬프트가 open_threads 기록을 명시적으로 요구 (prompt.ts)

[3] 압축 LLM 응답 후 ── 열린 스레드 회수                 (LLM 0)
    질의 = 요약이 낸 미해결 항목 문장 그대로 (최대 4개)
    키워드 30건(범위 밖 한정) + 임베딩(bge-m3) → RRF 융합(k=60)
    질의별 커서 라운드로빈으로 배분, 총 4건
    Ollama 없으면 키워드 순위로 무손실 폴백

[4] 동봉 ── md "## 관련 원문 (범위 밖)"
    각 항목에 시각·턴id·연결강도·회수경로(via)·원문 인용
    ※ 요약을 다시 쓰지 않는다 (아래 5절)

[5] 소비 ── 사람이 읽기 / 다른 AI에 붙여넣기 / 압축 갈래로 워프
```

## 5. 설계 원칙 — 왜 "덧붙이기"이고 "재작성"이 아닌가

1. **비용**: 요약을 다시 쓰려면 LLM을 한 번 더 불러야 한다. "추가 호출 0" 목표와 정면충돌.
2. **귀속 오염 방지** (이쪽이 더 중요): 범위 밖 정보를 요약 문장에 녹이면 **"이 구간에서 실제로 일어난 일"과 "다른 데서 끌어온 참고"의 경계가 사라진다.** 이어받는 AI가 범위 밖 사실을 범위 안 사실로 착각하면 그게 환각의 씨앗이다.
3. **오류 비용 제한**: 지금 구조는 리트리버가 틀려도 "무관한 참고 한 줄"로 끝난다. 재작성 방식이면 잘못된 회수가 요약에 녹아 걸러낼 수 없다.

## 6. 측정 지표

### 6.1 열린 스레드 회수 품질 (핵심 지표)

**측정 방법**: 지난 압축 11건이 **실제로 생성한** `open_threads`·`todo` **72건**을 질의로 사용(연구자가 만든 질의가 아님). 회수 결과 539쌍을 조건 라벨을 숨긴 채 LLM이 유관/무관/판단불가로 판정.

| 조건 | hit@3 | precision@3 | 전부 무관 |
|---|---|---|---|
| 종전(식별자 추출 + 3점 문턱) | 66.7% | 50.5% | 31.9% |
| 원문 질의 키워드만 | 70.8% | 49.5% | 27.8% |
| **임베딩 단독** | 66.7% | **46.3%** | 29.2% |
| **하이브리드 (채택)** | **80.6%** | **60.2%** | **18.1%** |

- 순이득 **+10건/72** (13건 건짐, 3건 밀림)
- **임베딩 단독이 종전보다 나쁘다** — 대체가 아니라 **융합**이어야 한다는 근거

### 6.2 종전 설계가 실제로 작동하지 않았던 증거

- 종전 게이트(`키워드 top1 < 3점이면 임베딩`)는 **72건 중 0건** 진입. 이 코퍼스의 키워드 점수 분포가 6.4~124.7이라 3점 문턱이 스케일에 맞지 않았다 → 임베딩이 배포돼 있는데 한 번도 호출되지 않음.
- 질의 변환(`identTokens`)은 **72건 중 54건(75%)**이 빈 배열. 열린 스레드가 한국어 문장이라 식별자가 안 나온다 → 제거.
- 슬롯 배분 실측 커버리지 평균 **2.6/4** → 커서 라운드로빈으로 교정.

### 6.3 검색 경로 (같은 엔진의 다른 소비처)

- 홀드아웃 60질의(결정론 샘플링) r@3 **98.3%**
- 패러프레이즈 질의(다른 어휘로 묻기) r@3 11.1% → **22.2%**
- 확신 게이트로 실사용 질의의 **90%는 임베딩 호출 자체를 생략**(지연 0 추가)

### 6.4 손실 복구 효과 (방향성 근거)

실범위 9턴 압축 후 자작 10문항을 "패키지만(A)" vs "패키지+리트리버(B)"로 답변·채점: **A 8/10 vs B 10/10**, 환각 양쪽 0. B가 이긴 2건은 전부 "결정↔근거 연결이 패키지에서 끊긴" 유형.
*(n=10·자작 문항·자기 채점 → 방향성 근거이지 통계 근거 아님)*

## 7. 대안 비교 — "범위 시작을 트리 첫 노드로 고정"

회의에서 제기된 대안을 실측 비교했다.

| | 첫 노드 고정 | **리트리버** |
|---|---|---|
| 트랜스크립트 | 8,983 → **50,538자 (5.6배)** · 긴 세션 4~7배 | 변화 없음 |
| 예산(120,000자) 초과 시 | **가장 오래된 턴부터 통째 삭제** | 해당 없음 |
| 추가 분량 | 입력이 4~7배 | 패키지 +13~15% |
| 세션 경계 | 같은 세션만 | **넘어감** |
| 확장성 | 세션이 길수록 붕괴 | 길이와 무관 |

**첫 노드 고정의 구조적 문제**: 예산을 넘는 순간 `transcript.ts`가 **가장 오래된 턴부터 버린다**. 즉 초기 맥락을 지키려고 첫 노드부터 포함했는데, **정확히 그 초기 부분이 제일 먼저 잘려나간다**(235턴 세션이 이미 118,211자로 한계선).

**리트리버의 실증**: "캡슐이 잘못 잘렸을 때 우클릭 합치기가 구현됐는지 미확인"이라는 미해결 항목에, **다른 세션(8/7)**의 *"캡슐은 의미 유사성을 주장하지 않는다 — 끊긴 게 확실한 지점에서만 자른다"* 턴을 회수했다. 질의 어휘("우클릭·합치기·overlay")가 그 턴에 하나도 없어 **키워드로는 못 찾고 임베딩만 찾는** 사례이며, 첫 노드 고정으로는 다른 세션이라 애초에 포함되지 않는다.

## 8. 정직한 한계

1. **표본**: n=72, 코퍼스 1개(화수 사용 기록). 다른 프로젝트에서 같은 수치가 나온다는 근거 없음.
2. **판정자**: haiku, 자기일관성 재판정 미실행 → 판정자 흔들림 미측정.
3. **잔여 오류**: 전부 무관 **18.1%** — 5건 중 1건은 여전히 헛것이 붙는다.
4. **환경 의존**: 위 80.6%는 임베딩이 켜졌을 때. **Ollama가 없으면 70.8%**(그래도 종전 66.7%보다는 낫다).
5. **캘리브레이션 상수**: `CONFIDENCE_TAU=1.63` 등은 이 코퍼스 스냅샷 기준. 다른 프로젝트에서 재보정이 필요할 수 있다(폴백이 무손실이라 파국은 아님).

→ **설계 결정 근거로는 충분하나, 제출물 공식 수치는 팀 질문지 A/B가 맡아야 한다.**
