# 공개 데이터셋 기반 compact 압축 실험 결과

> 2026-08-06 실행. compact 프롬프트 v3 → v3.4 최적화 과정과, 공개 세션 데이터셋 103개에 대한
> 절약율·품질·비용 실측 기록. 평가 지표 문서([2026-08-05-압축-평가-지표.md](./2026-08-05-압축-평가-지표.md))의
> §4.1(토큰 절감률·세션당 비용·key-fact recall) 시나리오를 처음으로 재현 가능한 표본으로 채운 실험이다.

## 1. 왜 공개 데이터셋인가

로컬 세션만으로는 표본이 작고(n=1\~2) 심사위원이 재현할 수 없다. Hugging Face에
Claude Code 네이티브 jsonl 형식 그대로의 공개 세션 데이터셋이 있어 이를 도입했다.

| 데이터셋 | 규모 | 라이선스 | 비고 |
|---|---|---|---|
| [trace-commons/agent-traces](https://huggingface.co/datasets/trace-commons/agent-traces) | 27세션 · 377턴 | **CC-BY-4.0** | 원본 무수정("only anonymized, never reshaped") — 보고서 인용에 적합 |
| [cfahlgren1/Fable-5-traces](https://huggingface.co/datasets/cfahlgren1/Fable-5-traces) | 79세션 · 478턴 | AGPL-3.0 | 소형 세션 다수. **로컬 측정만 사용, 재배포 금지** |

- 두 데이터셋 모두 **전부 영어 세션** — 한국어 품질(언어 보존·한국어 식별자)은 로컬 세션 트랙으로 별도 검증해야 한다.
- Fable-5에는 서브에이전트 기록(`agent-*.jsonl`) 36개가 포함되어 있으나 `fork-context-ref` 레코드가 없어
  fork 시각화 접합은 불가(파싱은 됨). 부모 세션의 Task 기록에서 agentId를 역추적하는 폴백이 파서 개선 후보.

**파서 강건성**: 106세션(855턴) 전부 파싱 성공, 실패 0. 다른 머신·다른 모델(minimax 등)·다른
버전의 Claude Code가 만든 jsonl을 전부 소화했다. 대화 턴이 0개인 파일 3개(Fable-5)만 측정 대상에서 제외.

## 2. 실험 방법

- `discover.ts`에 `BRANCHPORT_PROJECTS_ROOT` 환경변수 오버라이드 추가 — 실제 `~/.claude/projects`와
  격리된 루트에 "세션 1개 = 프로젝트 1개" 구조로 배치. 심사위원이 같은 데이터셋으로 재현 가능.
- 배치 러너 `오픈소스/probe-test/batch-compact.mjs`(로컬 전용, 미커밋): 프로젝트×모델 순차 실행,
  결과를 `runs.jsonl`(1행 1실행) + `summary.md`로 축적.
- 조건: 각 세션의 시간순 상위 **80% 턴** 선택, 기본 모델 sonnet, `claude -p --output-format json`으로
  비용·토큰·시간 실측(`meta.claude`).
- 압축률 표기: **잔존율 = 패키지 md 크기 / 렌더링 트랜스크립트 크기** (문자 기준. 같은 언어 안에서는
  토큰 절약율과 동일). 트랜스크립트는 이미 차등 캡으로 다이어트된 입력이므로 **보수적(하한) 수치**다 —
  원본 대화 전문 대비로는 절약율이 더 높다.

## 3. 프롬프트 최적화 여정 (v3 → v3.4)

### 3.1 언어 오염 버그 — 데이터셋이 즉시 잡아낸 배포급 결함

첫 파일럿(5세션×sonnet/opus) 10건 전부 **영어 세션인데 한국어로 요약**됐다.
원인: `claude -p`가 운영자의 전역 `~/.claude/CLAUDE.md`("Always respond in korean")를 로드해
프롬프트의 "트랜스크립트 주 언어로 작성" 규칙을 이긴 것. 로컬 한국어 세션에서는 절대 보이지 않는
오염이었다. 수정 과정:

1. 프롬프트에 우선순위 조항 추가 → **실패** (여전히 한국어)
2. `--bare` 플래그 → OAuth 인증 차단이라 **사용 불가**
3. **`--system-prompt`로 기본 시스템 프롬프트 대체** → CLAUDE.md 미로드 확인(프로브), 영어 출력 성공.
   단 CLI 공유 캐시를 못 읽어 비용 $0.26 → $0.46 회귀
4. **`--tools ""` 추가** (compact는 도구 금지 작업) → 도구 정의 제거로 입력 65,848 → 35,506토큰(-46%),
   비용 $0.278 회복

결과적으로 격리와 비용 절감을 동시에 확보. 어떤 사용자 머신에서든 재현될 수 있던 결함이라
공개 데이터셋 도입의 가치를 보여주는 실증 사례다.

### 3.2 품질 감사 → v3.1 정확성 규칙

3세션×패키지 5종을 원문 트랜스크립트와 교차 대조(병렬 감사 에이전트 3개)해 결함 패턴 6종을 실증:

| 패턴 | 사례 |
|---|---|
| 주체 오귀속 (최다) | 어시스턴트 권고·스킬 규칙이 「사용자 제약」으로 승격 |
| 인과 압축 | "수정 후 통과"의 시간적 인접을 "그 수정이 고쳤다"로 단정 |
| 절단 보간 | 잘린 명령·에이전트 출력을 완성형으로 복원해 확정 서술 |
| 에러 정의 흔들림 | 빈 에러 섹션 vs 예상된 실패까지 과포함 |
| 시점 스탬프 부재 | 코드 수정 전 관찰이 현재형으로 잔존 |
| 부채 미표기·함정 탈락 | expected 파일 우회 미기록, CRLF 개행 버그 통째 누락 |

→ v3.1: attribution(사용자 발화만 constraints) · causality(인접≠인과) · truncation(절단 보간 금지) ·
time-stamping(수정 전 관찰 한정) 규칙 신설 + errors/open_threads/gotchas 정의 보강.
**결함은 해소됐지만 출력이 부풀어 잔존율 12.6% → 23.9%로 악화.**

### 3.3 압축률 회복 → v3.4

- **밀도 규칙**(v3.2): 사실 1회 서술(섹션 간 중복 금지), 핸드오프 노트 문체 → 21.0%
- **동적 출력 예산**(v3.3): 트랜스크립트의 10%(3k\~8k자 클램프)를 프롬프트에 숫자로 주입 → 16.0%.
  단 **커밋 해시가 탈락하는 회귀** 발생
- **식별자 > 예산**(v3.4): "식별자·에러 문자열·수치·제약을 지키려면 예산 초과 허용" 명시 → 회귀 해소

검증은 감사 결함을 **회귀 앵커 8종**(CRLF 함정·fixture 인과·절단 명시·워크어라운드 부채·제약
verbatim·해시·PR#·미검증 스레드)으로 만들어 매 버전 표적 점검했다 — 전체 재감사보다 훨씬 싼 품질 감시 루프.

**최종: v3와 같은 크기, v3.1의 품질, 비용은 오히려 하락**($0.40 → $0.24). `src/prompt.ts` 커밋 `2e76295`.

## 4. 본 실험 결과 — 103세션 절약율 분포

성공률: **106회 중 실질 실패 0** (JSON 절단 4건은 전부 1회 재시도로 통과 — 이 실측을 근거로
서버에 자동 재시도를 구현, 커밋 `a38e621`). 총 비용 API 단가 환산 약 $21 (실제로는 구독 쿼터 소모).

| 트랜스크립트 규모 | 세션 수 | 가중 잔존율 | 절약율 |
|---|---|---|---|
| 초소형 (<5k자) | 36 | **168%** | **-68% (역효과)** |
| 소형 (5\~20k자) | 18 | 43.5% | 56.5% |
| 중형 (20\~60k자) | 22 | 25.2% | 74.8% |
| 대형 (>60k자) | 27 | 16.5% | **83.5%** |
| **전체 가중** | **103** | **21.4%** | **78.6%** |

데이터셋별: trace-commons 18.0% 잔존(중대형 위주), Fable-5 24.4%(소형 다수).

### 4.1 핵심 발견 — 손익분기점 ≈ 5,000자

**트랜스크립트 5,000자 미만(대략 3\~4턴 이하) 구간에서는 패키지가 원문보다 커진다.**
사실층·원문앵커·섹션 골격이라는 고정비 때문이며, 103세션 표본이 있어야 보이는 임계값이었다.

활용 두 가지:

1. **정직한 조건부 주장** — "compact는 \~5k자 이상에서 이득이며 세션이 클수록 효과가 커져
   대형에서 83.5%에 도달". 절감률 단독 주장("N배 압축")보다 방어력 있는 서사이며, 평가 지표
   문서의 "절감률은 보존율과 동시 보고" 원칙과도 일치한다.
2. **제품 반영 (커밋 `a38e621`)** — `POST /api/compact/estimate`(임계값 `COMPACT_MIN_CHARS=5000`)
   신설. UI는 범위 선택 즉시 견적을 조회(350ms 디바운스)해 미달이면 선택 노드·경로·선택 바를
   빨간색으로 표시하고, 생성 버튼은 "그래도 생성" 2단계 확인으로 전환된다.

### 4.2 모델 비교 (sonnet vs opus)

| | sonnet | opus |
|---|---|---|
| 비용/회 (v3 파일럿 5세션 평균) | $0.417 | $0.631 (1.51배) |
| 시간 | 72초 | 76초 |
| 사실 오류 (정밀 대조 1쌍) | 0 | 0 |
| 서술 품질 | 양호 | 결정·에러 서사가 더 촘촘, 식별자 보존 우수 |
| 안정성 | 내부 3턴 재시도 1회 발생 | 전 회 1턴 |
| v3.4 출력 크기 (동일 2세션) | 9,734 / 15,730자 | **7,826 / 13,581자 (14\~20% 더 작음)** |

권고: **품질 기본값 opus, 비용 민감 시 sonnet** — 단가 차이는 1.5배 수준이고, v3.4에서는 opus가
예산 준수(압축)도 더 정확하다.

## 6. 한계와 주의

- 절약율의 분모는 차등 캡 적용 후 트랜스크립트 — **보수적 하한**이다 (로컬 세션 실측에서 원본
  슬라이스 대비 렌더링은 약 29% 수준이었으므로, 원본 기준 절약율은 95% 안팎으로 추정).
- 컷 지점 80% 고정 — 앵커 위치별 곡선(30/50/70/90%)은 미실측. 재개 시 tail(비압축) 이어붙임을
  포함한 전체 절약은 이보다 낮다(8-03 로컬 실측: 81% 앵커에서 전체 3.96배).
- 비용 수치는 `total_cost_usd` — **API 단가 환산 추정치**이며 구독(OAuth) 사용 시 실제 청구가 아니라
  플랜 쿼터 소모다. 문서·발표에 쓸 때 "API 단가 환산 기준" 명시 필요.
- 품질 평가는 감사 3세션 + 회귀 앵커 8종 — key-fact recall **자동 채점**(사실층을 정답지로)은 미구현.
- 영어 세션 결과다. 한국어 세션의 언어 보존·절약율(한글 \~1.2자/토큰)은 로컬 트랙에서 별도 측정 필요.

## 7. 재현 방법

```bash
# 1) 데이터셋 다운로드 (오픈소스/probe-test/datasets/ — 커밋 금지, 로컬 전용)
hf download trace-commons/agent-traces --repo-type dataset --local-dir 오픈소스/probe-test/datasets/trace-commons
# 세션당 프로젝트 디렉터리(tc-xxxxxxxx/<uuid>.jsonl)로 복사 배치

# 2) 격리 루트로 서버 기동
BRANCHPORT_PROJECTS_ROOT=<datasets/projects 절대경로> PORT=4301 node dist/server.js

# 3) 배치 실행
node 오픈소스/probe-test/batch-compact.mjs --server http://127.0.0.1:4301 \
  --models sonnet --cut 0.8 --out 오픈소스/probe-test/batch-results/sweep-v34
```

원자료: `오픈소스/probe-test/batch-results/sweep-v34/`(27세션) · `sweep-v34-fable5/`(76세션),
각 `runs.jsonl` + `summary.md`. 생성된 패키지 실물은 `packages/tc-*`, `packages/f5-*`.
