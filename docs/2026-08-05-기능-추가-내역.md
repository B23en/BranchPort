# BranchPort 기능 추가 내역 (2026-08-05 묶음)

팀장님 TS판을 베이스로, prototype에서 검증했던 파이프라인을 옮기고 그 위에 세션 뷰·캡슐·포탈·갈래를
붙인 결과물입니다. 아래는 "화면에서 뭐가 달라졌는지 → 내부에서 어떻게 도는지 → 어디를 보면 되는지" 순서로
기능별 정리입니다. 못 하는 것과 알려진 한계도 끝에 그대로 적었습니다.

실행: `npm install && npx tsc -p . && node dist/server.js` → http://127.0.0.1:4300

---

## 1. 세션 뷰가 기본 화면이 됐다

열면 프로젝트 전체 트리 대신 **가장 최근에 사람이 대화한 세션 하나**가 가로 한 줄로 나옵니다.
헤더의 세션 셀렉터로 다른 세션·전체 트리로 바꿀 수 있습니다.

셀렉터는 네 그룹입니다.

- **세션** — 사람이 직접 대화한 것만
- **⑂ 갈래** — 노드에서 확장한 갈래 대화 (아래 5절)
- **에이전트·도구 기록** — 서브에이전트 실행 기록 등
- **전체 트리** — 기존 팀장님 화면 그대로 (이 코드 경로는 손대지 않고 렌더러를 분리했습니다)

사람/에이전트 구분은 턴 수 추측이 아니라 저장 구조로 합니다. `~/.claude/projects/<프로젝트>/` 루트의
`UUID.jsonl`이 사람 세션이고, `<세션>/subagents/agent-*.jsonl`이 에이전트 기록입니다.
서버가 `/api/turns` 응답에 `humanSessions` 목록을 실어 보냅니다.

구현: `public/index.html`의 `renderSession()` / `rebuildSessionSelect()`, `src/server.ts`의 `/api/turns`.

## 2. 노드마다 LLM이 지은 제목과 요약이 붙는다

노드 밑 라벨과 카드 상단이 원문 절단이 아니라 **생성된 제목(12자 명사구) + 요약(무엇을 요청받아
어떻게 했고 결과가 뭔지, 100자)**으로 바뀝니다. 요약은 호버 툴팁과 카드에서 보입니다.

동작 방식:

- 40턴씩 묶어 로컬 `claude -p --json-schema` 한 번 호출. 응답은 JSON으로 강제되고, 정규식 파싱은
  실패 시 안전망으로만 씁니다.
- 결과는 `labels/<프로젝트>.json`에 **내용 해시** 키로 캐시됩니다. 해시에 턴의 끝 시각이 섞여 있어서,
  진행 중이던 턴이 나중에 더 자라면 해시가 바뀌고 자연히 다시 생성됩니다.
- 방금 끝난 턴(5분 이내)은 아직 대화가 진행 중일 수 있어 건너뛰고, 3분 주기로 재시도해 채웁니다.
- 생성 순서는 ① 지금 보고 있는 세션 ② 사람 세션 최신순 ③ 에이전트 기록 순입니다.
- 라벨이 아직 없는 턴은 원문을 흐린 기울임(임시 표시)으로 보여주고, 도착하는 대로 교체합니다.
  좌상단에 "제목 생성 중… n/전체" 카운터가 뜹니다.

체감 시간: 40턴까지는 호출 한 번(대략 20초~1분), 더 길면 40턴 단위로 나눠 호출합니다.
한 번 만들면 캐시라 그다음은 즉시.

구현: `src/server.ts`의 `/api/label`·`/api/labels`, `public/index.html`의 `refreshLabels()`.

## 3. 긴 세션은 캡슐로 접힌다

20턴 이상의 세션은 연속 구간이 알약 모양 **캡슐**로 접힙니다. 캡슐에는 구간 첫 턴의 제목, 턴 수,
안에 든 턴들의 국면색 점띠가 보입니다. 클릭하면 제자리에서 펼쳐지고(펼친 범위는 점선 영역으로 표시),
`⟨ 접기`로 다시 접습니다. shift+클릭하면 캡슐 통째로 압축 범위에 들어갑니다.

어디서 자르는지가 중요한데, 의미 추측이 아니라 **파일에 기록된 확실한 신호**에서만 자릅니다:
30분 이상 공백, compact 경계(⑊). 그리고 에러 턴·포크 지점·갈래 달린 턴·마지막 5턴은
절대 캡슐에 삼켜지지 않습니다. 접기는 요약과 달리 정보 손실이 없어서(펼치면 전부 나옴),
경계가 다소 틀려도 비용이 "클릭 한 번"입니다.

구현: `public/index.html`의 `buildSessionElements()` / `makeCapsule()`.

## 4. 포크 지점은 ◇ 포탈로 건너간다

세션 선에서 에이전트에게 위임했거나 갈라져 나간 지점에는 보라 ◇ 노드가 매달립니다.
호버하면 건너편의 첫 턴 제목·요약이 미리 보이고, 클릭하면 그 세션 뷰로 전환됩니다.
좌상단에 브레드크럼(`⟨ 원래 세션`)이 쌓여 언제든 되돌아오고, 갈라져 나온 세션 쪽 시작점에는
↩ 역방향 포탈이 붙습니다.

이 과정에서 파서 버그 하나를 고쳤습니다. 기존 접합 로직은 에이전트 파일 안에 `fork-context-ref`
레코드가 있다고 가정하는데, 최신 포맷에는 그 레코드가 없습니다(실측). 그래서 에이전트 기록 19개가
전부 고아로 떠 있었습니다. 접합점을 세 단계로 찾도록 바꿨습니다:

1. `fork-context-ref`가 있으면 그대로 (구 포맷 호환)
2. 없으면 부모 세션 파일에서 해당 agentId를 언급한 레코드의 uuid에 접합
3. 그것도 없으면 에이전트 시작 시각 직전의 부모 세션 마지막 노드에 접합 (시간 폴백)

이 프로젝트에서 고아로 떠 있던 에이전트 기록 대부분이 연결됐습니다(마지막 검수 시점 기준
16개 중 14개). 남는 소수는 API 에러로 체인이 끊긴 옛 기록이라 접합 불가가 정상이고,
셀렉터의 에이전트 그룹에 격리되어 있습니다.

구현: `src/tree.ts`의 `findAgentRefUuids()`와 접합 우선순위, `public/index.html`의 `goPortal()`.

## 5. 노드에서 갈래를 열면 별도 화면으로 워프한다

노드의 ⑂ 배지를 누르면(또는 카드의 갈래 칩, 압축 모달의 "이 패키지로 갈래") 그 갈래의 전용
화면으로 전환됩니다. 왼쪽에 분기 지점 턴이 유령 노드(점선)로 서 있고, 오른쪽으로 문답이 노드로
이어지며, 하단 입력바로 계속 질문할 수 있습니다. 갈래는 세션 셀렉터에도 "⑂ 이름" 항목으로 올라가서
포크 세션과 같은 방식으로 오갈 수 있습니다.

갈래 AI가 받는 맥락: **첫 턴부터 분기 지점까지의 흐름(턴별 제목+요약) + 분기 지점 턴의 원문 전체**.
압축 범위에서 만든 갈래라면 압축 패키지 본문이 맥락입니다. 분기 지점 이후의 일은 모르는 상태로
대화합니다 — 실제로 물어보면 "이 시점 이후는 정보가 없다"고 답합니다.

한계도 그대로 적습니다. 이 갈래는 Claude Code의 실제 세션 파일이 아니라 BranchPort가
`branches/<프로젝트>.json`에 저장하는 대화입니다(Claude Code가 외부 세션 주입을 지원하지 않음).
응답은 `claude -p` 호출이라 턴당 수십 초 걸리고, 갈래 안에서는 대화만 가능합니다 —
파일 편집·도구 실행은 없습니다.

구현: `public/index.html`의 `renderBranchView()` / `sendBranchWarp()`, `src/server.ts`의
`/api/branch-create` / `/api/branch-chat`.

## 6. 압축 패키지가 세 층으로 두꺼워졌다

shift+클릭이나 챕터 바 드래그로 범위를 잡고 압축하면, 예전의 "요약 + 사실층"에 더해:

- **상태층** — 원본 JSONL을 세션별 시간창으로 다시 훑어 실제 파일 diff(+n/−n, 샘플)와
  에러 원문 스니펫을 동봉합니다. LLM을 거치지 않는 결정론 층이라 요약이 뭉개져도 이건 정확합니다.
  시크릿(API 키 등)은 마스킹됩니다.
- **계보** — 이 구간이 속한 세션, 구간 앞의 같은 세션 선행 턴 수, 그리고 "세션 X는 세션 Y의
  '○○' 지점에서 갈라짐" 식의 부모 분기 체인. 패키지를 받은 쪽이 어느 트리의 어느 가지에서
  온 대화인지 알 수 있습니다.
- **목적 셀렉트** — 받는 쪽 용도(이어서 구현 / 버그 수정 / 팀원 설명)를 고르면 요약 프롬프트의
  우선순위가 바뀝니다. (2026-08-09에 한국어 한 줄 힌트 → 영어 수신자 프로파일 블록 v3.8.1로
  승격, A/B 실측은 평가 지표 문서 §2 "목적 프로파일 A/B" 참고)
- **/api/expand** — 패키지에 적힌 앵커 id로 턴 원문을 언제든 다시 꺼낼 수 있고, 패키지 안에
  curl 사용법이 함께 적힙니다. 압축은 삭제가 아니라 접기라는 원칙의 인출 통로입니다.

구현: `src/server.ts`의 `handleCompact()` / `collectStateLayer()` / `/api/expand`.

## 7. 자동 갱신, 로딩, 기타

- **자동 갱신**: 10초마다 세션 파일 수정 시각만 확인하고, 실제 턴 내용이 바뀐 경우에만
  애니메이션·카메라 이동 없이 제자리 갱신합니다. 카드·모달·범위 선택·갈래 응답 대기 중에는
  건드리지 않습니다.
- **로딩 오버레이**: 압축 생성과 갈래 응답 대기 두 곳에서, 스플래시와 같은 노선도 애니메이션
  (선 위로 대시가 흐르고 역이 숨쉬는) 카드가 뜹니다. 클릭을 막지 않습니다.
- **챕터 바**: 세션 뷰 하단의 국면색 눈금 바. 클릭하면 그 턴으로 이동(접힌 캡슐이면 펼치고),
  드래그하면 그 구간이 압축 범위로 잡힙니다.
- **팔레트**: 색각 검증을 통과한 3색(실행 파랑 / 편집 주황 / 탐색 청록)으로 교정했습니다.
  이전 청록·녹색 조합은 실행↔탐색 색차가 판별 기준 미달이었습니다.

## 8. 파서 보강 — 끼어든 질문 복원과 시스템 텍스트 필터

에이전트가 작업하는 도중에 사용자가 보낸 메시지는 세션 파일에 일반 질문 레코드가 아니라
`queue-operation`이라는 별도 타입으로 저장됩니다. 이 레코드는 uuid가 없어서 기존 파서가
통째로 버렸고, 그래서 그 뒤의 답변 턴이 질문 없이 "(계속)"으로 남았습니다.

지금은 큐 기록의 세 가지 동작을 구분해 되살립니다. enqueue는 입력, **dequeue는 실제
전송 확정, remove는 보내기 전에 사용자가 지운 것**입니다(실측: dequeue된 것의 86%가
정식 질문이 되고 remove된 것은 0.3%뿐). 그래서 **dequeue로 확정된 것만** 복원 후보로
삼습니다 — enqueue만 믿으면 쓰다가 지운 초안을 질문으로 날조하게 됩니다.
한 가지 더: remove 기록의 상당수는 content 필드가 없어 무엇을 지웠는지 특정할 수 없습니다.
그런 기록을 만나면 그 시점부터 해당 파일의 큐 복원을 중단합니다 — 지운 초안을 살리는 것보다
"(계속)"으로 남기는 쪽이 낫다는 원칙입니다.

복원은 두 단계입니다. 먼저 끼어든 시각마다 응답 체인을 끊어 **메시지 하나당 턴 하나**가
생기게 하고(안 끊으면 한 작업 동안 여러 번 끼어든 메시지 중 하나만 자리를 얻습니다),
그다음 각 턴에 시간 순서로 질문을 배정합니다. 이때 세 가지를 거릅니다.

- task-notification 같은 시스템 주입 텍스트도 큐로 들어오므로, `<하이픈-포함-태그>`로
  시작하는 텍스트는 배정하지 않습니다. 하이픈을 조건으로 건 이유: 사용자가 `<div>` 같은
  HTML을 붙여넣으며 질문하는 경우까지 걸러버리지 않기 위해서입니다.
- 큐에 들어갔던 메시지가 나중에 정식 질문 레코드로도 기록되는 경우가 있어, 이미 진짜 턴이
  된 질문은 다시 배정하지 않습니다(중복 방지).
- 복원된 턴은 내용 해시가 바뀌므로 제목·요약도 복원된 질문 기준으로 다시 생성됩니다.

분류가 맞는지는 실데이터 전수 감사로 확인했습니다(2026-08-05 시점, 이 저장소 프로젝트의
사람 세션 3개 기준 — 데이터가 계속 자라므로 수치는 시점 표기). 질문으로 인정된 것을 전부
눈으로 확인해 시스템 텍스트 혼입 0건, 걸러진 것은 전부 task-notification류 시스템 주입,
복원 후 중복 질문 턴 0건이었습니다. 끼어든 메시지 추적에서는 전송 확정된 메시지가 자기
노드쌍을 얻는 것(배정 시간차 중앙값 1분 미만)과, 취소된 초안이 질문으로 부활하지 않는 것을
확인했고, remove에 content가 없는 다른 프로젝트들에서는 복원 중단 규칙이 작동하는지를
별도로 검증했습니다.

## 데이터 파일 (커밋 금지)

`labels/`, `branches/`, `packages/`는 대화 내용에서 파생된 데이터라 전부 gitignore에 있습니다.
공유할 때 이 폴더들이 딸려가지 않게 주의하면 됩니다.

## 검증 방법

- 빌드: `npx tsc -p .` 통과, UI 스크립트는 node --check 통과
- 라벨: 실프로젝트 168턴 전량 생성(오류 0), 캐시 재사용 확인
- 갈래: 이전 흐름 요약 정확, "이 시점 이후는 모른다" 답변 확인
- 압축: 상태층에 실제 diff·에러 스니펫 포착, 계보 섹션 생성 확인
- 코드 리뷰: 별도 검수 에이전트를 여러 차례 돌려 발견된 문제를 그때그때 수정
  — 대표적으로 갈래 응답 후 로딩이 안 사라지던 문제, 첫 클릭 후 자동 갱신이 영구 정지하던 문제,
