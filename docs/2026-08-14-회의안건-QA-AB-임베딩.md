# 회의 안건 — 공식 QA A/B 실행 계획과 임베딩 결정 (2026-08-14, 화수)

두 안건은 연결돼 있습니다: A/B 결과가 임베딩 결정의 마지막 근거가 됩니다.

## 안건 1. 공식 QA A/B — "리트리버가 보존율을 얼마나 올리는가"

지금까지의 숫자(미니 A/B 8/10→10/10, 패러프레이즈 실측 등)는 전부 시스템을 만든 사람이
문항을 만들고 채점한 것이라 **방향 판단용**입니다. 제출물에 넣을 공식 숫자는 문항 작성자와
시스템 제작자를 분리해야 방어가 됩니다.

**분업 제안** (MS.LIM의 feat/compact QA 방법론 재사용):

| 역할 | 담당 | 내용 |
|---|---|---|
| 평가 키트 준비 | 화수 | 대상 세션 선정, 문항 작성 가이드(유형·개수), A/B 자동 실행 스크립트, 기계적 채점 기준표 |
| **질문지 작성** | **팀원** | 압축 대상 구간을 보고 질문 작성 — 시스템을 안 만든 사람이 쓰는 것이 핵심 |
| 실행·집계 | 화수 | A(패키지만) vs B(패키지+리트리버) 자동 실행, 기준표대로 채점 |

- 문항 유형 배분 제안: 수치·파일명형 / 결정·이유형 / 개념어형(원문과 다른 어휘로 묻기) 각 1/3 —
  마지막 유형이 임베딩 필요성 판정에 직결됩니다.
- 키트는 화수가 회의 전까지 준비. 팀원 소요는 구간당 질문 5~10개 작성뿐.

## 안건 2. 임베딩 선택층 도입 여부

**8/14 업데이트 — 판단 재료가 늘었습니다:**

1. **헤드룸 실측**: 패러프레이즈 질의(원문과 다른 어휘) 9개 중 4개가 현행 키워드 검색에서 실패
   (알약↔캡슐, 색약↔색각 류 동의어 갭). 식별자형은 r@3 98.3%로 포화. 즉 임베딩이 필요한
   실패 유형이 실재하며, 남은 질문은 "실사용 질의 중 이 유형이 몇 %냐"(→ 안건 1이 답함).
2. **구현 실현성**: Ollama 선택층(있으면 융합, 없으면 무손실 폴백)은 npm 의존성 0으로 구현·
   검증됨 — "서드파티 0" 방침 훼손 없음. transformers.js(자동 다운로드)와는 별개 안건.
3. **모델 실측 확정: bge-m3** — 공개 벤치는 qwen3-embedding:0.6b 근소 우위였으나, 자체
   평가셋에서 bge-m3가 전 지표 승리(홀드아웃 MRR 0.898 vs 0.836, 확신 게이트 조건에서
   qwen3는 가드레일 미통과). 벤치 순위가 도메인 실측과 뒤집힌 사례로 기록.
4. **융합 방식 실측 확정: 확신 게이트 조건부 융합** — 균일 RRF는 8개 파라미터 조합 전부
   가드레일 실패(키워드 강점 잠식). 채택안: 키워드 top1 뾰족함(top1/top10중앙값) ≥ τ=1.63
   (홀드아웃 승자 분포 p10에서 캘리브레이션, 평가셋과 분리)이면 키워드 경로 그대로(실측
   90%가 이 경로 — 시맨틱 호출 생략으로 지연 0 추가), 미만이면 kw풀 200+RRF 융합.
   결과: 홀드아웃 r@3 98.3% 유지(퇴보 없음), 패러프레이즈 r@3 11.1%→22.2%·MRR
   0.111→0.189 (n=9라 절대 수치는 작음 — 방향성 근거). Ollama 부재 시 무손실 폴백 검증.
   τ는 코퍼스 스냅샷 기준이라 구성이 크게 바뀌면 재보정 필요(코드 주석에 명시).

**제안**: ① 하이브리드(키워드+임베딩 RRF) 구현을 브랜치에 포함해 리뷰받고 ② 공식 A/B에서
개념어형 문항의 비중·성적을 확인한 뒤 ③ 기본 활성화 여부를 결정. 폴백 구조라 Ollama가
없는 환경에서는 어떤 경우에도 현행과 동일하게 동작합니다.
